# 反馈与联系

作者遇到问题时最不该做的事，是被要求先去注册、先去找网页、先去填表。反馈由你代为提交，一句话就够。

## 两条通道

**已连接云端**：调用 `feedback_submit` 工具，不扣费。

**尚未连接云端**（还没授权，或者正因为连不上而受挫）：直接调接口，**不需要任何凭证**：

```
POST https://blackstone.wansu.tech/api/feedback
Content-Type: application/json

{
  "message": "作者的原话",
  "category": "bug",
  "contact": "",
  "edition": "longform-fiction",
  "client": {"client": "WorkBuddy", "client_version": "...", "skill_version": "...", "os": "darwin"}
}
```

有口令时加上 `Authorization: Bearer <token>`，反馈会归属到作者账号，方便后续回访；没有就匿名提交。**不要因为没连上云端就把反馈拦下来**——这类反馈恰恰最该被听见。

`category` 取 `bug`、`idea`、`writing`、`billing`、`other` 之一。判断不了就用 `other`，不要为此追问作者。

## 什么时候主动提议

不要频繁问"满意吗"。只在这些时刻提议一次，作者拒绝就不再提：

- 作者明确表达不满、困惑或"这个不好用"；
- 同一个操作连续失败两次以上；
- 作者提出一个当前做不到的需求（这是最有价值的反馈来源）；
- 作者主动说"我想反馈""能不能加个功能"。

一次会话最多主动提议两次。

提议话术：

> 这个我记下来反馈给黑石团队，可以吗？我会把你刚才说的原话带上。

## 提交规则

1. **必须先征得同意**，并复述将要提交的内容。未经确认不得提交。
2. 提交作者的原话，不要替他润色成"产品建议体"——原话里的火气和具体场景才是有用的信息。
3. **不要把正文、人物设定或作品内容放进反馈**。确实需要举例时，先问作者是否同意，并只带最小的片段。
4. `contact` 只在作者主动给出时才填，不要索要手机号或邮箱。已登录的作者不需要填。
5. 提交成功后一句话确认即可：

   > 已经反馈过去了。

   不要承诺什么时候修、会不会做。

## 作者要找人

作者问"怎么联系你们""有没有客服"时，告诉他反馈就是最直接的通道，你可以立刻替他提交。他坚持要自己看网页时，给 `https://blackstone.wansu.tech`，见 [about.md](about.md)。

不要编造客服电话、邮箱、微信群或工单系统。
