# 版本与更新

技能会持续改进。作者不该为此操心，也不该因为装的是旧版本而遇到已经修好的问题。更新由你负责，默认无感完成。

## 当前版本

以技能目录下的 `VERSION.md` 为准。读取它，不要凭记忆报版本号。

## 什么时候检查

在下面这些时机检查，且**每天最多检查一次**：

- 本次会话第一次使用黑石相关能力时；
- 云端调用出现与版本相关的错误（工具不存在、参数不被识别）时，这时无视每日限制，立即检查。

不要在每轮对话都检查，也不要为了检查而打断正在进行的写作。

检查记录写在 `~/.blackstone/skill-state.json`：

```json
{"installed_version": "1.1.0", "last_checked": "2026-08-08T10:00:00Z", "last_updated": "2026-08-08T10:00:00Z"}
```

文件不存在就新建。距离 `last_checked` 不足 24 小时，直接跳过检查。

## 怎么检查

```
GET https://blackstone.wansu.tech/api/public/skills/longform-fiction/manifest
```

返回 `version`、`download_url`、`install_dir`、`file_count` 和 `files`（每个文件的 `path`、`size`、`sha256`）。

网络不可用或请求失败时，**静默跳过**：更新检查失败不是作者的问题，不要报错、不要提示，把 `last_checked` 照常更新，下次再说。

## 什么时候更新

远端 `version` 高于本地 `VERSION.md` 时更新。版本号按 `主.次.修订` 逐段比较数字，不要按字符串比较——`1.10.0` 高于 `1.9.0`。

远端版本不高于本地时什么都不做，也不要告诉作者"已是最新版本"，除非他主动问起。

## 怎么更新

1. 下载清单里 `tarball_url` 指向的 `.tar.gz` 到临时目录。**用它，不要用 `download_url` 的 zip**：`tar -xzf` 在 macOS、Linux 和 Windows 上都能用同一条命令解开，而解 zip 需要按平台换命令；
2. 解压到一个临时目录，**不要直接覆盖正在使用的技能目录**——中途失败会留下一个半新半旧、两边都跑不起来的技能。

   ```bash
   tar -xzf <包> -C <临时目录>
   ```

   这一条走不通时，改用 `download_url` 的 zip，并按安装协议
   `https://blackstone.wansu.tech/install/blackstone.md` 的"二、安装"挑当前系统能用的命令。
   **不要预设机器上有 `python3`**，也不要在 Linux 上用 `tar -xf` 解 zip；这两条是更新失败最常见的原因。解压方式以那份协议为准，不要在这里另立一套；
3. 按 `files` 逐项核对 `sha256`。有任何一项不符就放弃这次更新，删除临时目录，静默跳过；
4. 校验通过后，再替换技能目录的内容。**必须删除清单里没有的旧文件**，不能只是覆盖同名文件——版本之间文件会改名或被移除，只做覆盖会在目录里留下一批再也不会被读到的残骸，还会让"文件数与清单一致"这项校验误判成失败；
5. 更新 `~/.blackstone/skill-state.json` 的 `installed_version` 和 `last_updated`。

作者的其他技能、其他配置一概不动。

## 怎么告诉作者

更新是后台动作，不需要作者批准，也不需要他做任何事。完成后**只在本轮回复末尾加一句**，然后继续原本的任务：

> （黑石写作技能已更新到 1.2.0。）

不要为此单独回复一轮，不要罗列改动清单，不要问"要更新吗"。但**这一句不能省** —— 静默更新是件影响作者控制权的事，做了就要让他知道，见 [security.md](security.md)。

作者说不想自动更新时，本次会话内不再检查，并告诉他随时可以说"黑石，更新技能"手动更新。

有一种情况必须多说一句：更新后需要新开会话才能生效时（多数客户端如此），补一句：

> 新版本会在你下次新开对话时生效，当前对话不受影响。

## 更新失败

不要重试，不要报错打断写作。把 `last_checked` 更新掉，用当前版本继续工作。只有在作者正遇到的问题确实由旧版本引起时，才告诉他：

> 我这边的写作技能有个新版本能解决这个问题，但自动更新没成功。你可以在新对话里说一句「黑石，更新技能」，我再试一次。

## 上报版本

发起设备授权时，在 `client` 里带上 `skill_version`，见 [account.md](account.md)。这让服务端知道哪些版本还在使用，从而判断某个旧接口能不能下线。
